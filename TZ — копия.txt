# Техническое задание  
## Сервис-трекер задач для онлайн-школы: контроль прохождения обучения учеником 8 класса

**Рабочее название продукта:** Учебный трекер 8 класс  
**Тип продукта:** веб-сервис  
**Основной сценарий:** учитель / куратор назначает учебные задачи по предметам, ученик выполняет, родитель / учитель видит прогресс, статусы, оценки и отчёты.  
**Аналог:** упрощённая Jira для учебного процесса.  
**Язык интерфейса:** русский.  
**Платформа:** браузер, адаптивная версия для компьютера, планшета и телефона.

---

# 1. Цель продукта

Создать простой трекер учебных задач для ученика 8 класса, который позволяет:

1. Вести список предметов ученика.
2. Назначать задачи по каждому предмету: домашние задания, уроки, проекты, тесты, сочинения, практические работы и т.д.
3. Отслеживать статус выполнения: запланировано, в работе, на проверке, выполнено, нужно доработать.
4. Контролировать дедлайны и просрочки.
5. Хранить материалы задания и ответ ученика: файлы, ссылки, комментарии.
6. Видеть прогресс по каждому предмету и по обучению в целом.
7. Выставлять оценки / баллы.
8. Формировать простые отчёты для учителя и родителя.

|---|---|
| Ученик | видит свои задачи, меняет статусы, прикрепляет ответы, комментирует |

| Администратор | управляет пользователями, предметами, настройками сервиса |

# 5. Роли и права доступа

## 5.1. Матрица прав

| Функция | Администратор | Учитель | Ученик | Родитель |
|---|---:|---:|---:|---:|
| Управление пользователями | Да | Нет | Нет | Нет |
| Управление предметами | Да | Да | Нет | Нет |
| Создание задач | Да | Да | Нет | Нет |
| Редактирование задач | Да | Да | Частично | Нет |
| Удаление задач | Да | Да | Нет | Нет |
| Изменение статуса задачи | Да | Да | Частично | Нет |
| Загрузка ответа ученика | Да | Да | Да | Нет |
| Комментирование | Да | Да | Да | Только чтение или комментирование, если разрешено |
| Выставление оценки | Да | Да | Нет | Нет |
| Просмотр прогресса | Да | Да | Свой | Своего ребёнка |
| Просмотр отчётов | Да | Да | Свой | Своего ребёнка |
| Экспорт отчётов | Да | Да | Нет / опционально | Нет / опционально |
| Настройка уведомлений | Да | Да | Да | Да |

## 5.2. Уточнение по ученику

Ученик может:

- смотреть свои задачи;
- переводить задачу из «К выполнению» в «В работе»;
- переводить задачу из «В работе» в «На проверке», если прикрепил ответ или отметил выполнение;
- добавлять комментарии;
- загружать файлы ответа;
- отмечать пункты чек-листа;
- указывать фактическое время, если это поле используется.

Ученик не может:

- удалять задачи;
- менять предмет, срок, тип задания, максимальный балл;
- переводить задачу в «Выполнено» без проверки учителя, если включена обязательная проверка;
- менять чужие задачи.

## 5.3. Уточнение по родителю

Родитель видит:

- список предметов;
- прогресс по предметам;
- выполненные, текущие и просроченные задачи;
- оценки;
- уведомления о просрочках и новых оценках.

Родитель не может:

- создавать задачи;
- менять статусы;
- редактировать оценки;
- удалять комментарии и файлы.

# 7. Статусная модель задачи

Статусы должны быть простыми, но похожими на Jira.

## 7.1. Базовые статусы

| Статус | Название | Описание |
|---|---|---|
| `backlog` | Запланировано | задача создана, но ещё не назначена к активной работе |
| `todo` | К выполнению | задача готова к выполнению учеником |
| `in_progress` | В работе | ученик начал выполнение |
| `review` | На проверке | ученик отправил работу учителю |
| `done` | Выполнено | учитель принял работу |
| `rework` | Нужно доработать | учитель вернул работу на доработку |
| `canceled` | Отменено | задача отменена |

---

## 7.2. Дополнительные цветовые метки

Не являются отдельными статусами, но показываются в интерфейсе:

| Метка | Условие |
|---|---|
| Просрочено | срок прошёл, статус не `done` и не `canceled` |
| Сегодня | срок выполнения сегодня |
| Завтра | срок выполнения завтра |
| На этой неделе | срок входит в текущую неделю |

---

## 7.3. Переходы статусов

| Текущий статус | Кто может перевести | Допустимые следующие статусы |
|---|---|---|
| Запланировано | учитель, админ | К выполнению, В работе, Отменено |
| К выполнению | учитель, ученик, админ | В работе, Отменено |
| В работе | ученик, учитель, админ | На проверке, К выполнению, Отменено |
| На проверке | учитель, админ | Выполнено, Нужно доработать, В работе |
| Нужно доработать | ученик, учитель | В работе, К выполнению |
| Выполнено | учитель, админ | Нужно доработать, В работе |
| Отменено | учитель, админ | К выполнению |

---

## 7.4. Правила статусов

1. Ученик не может сам перевести задачу в `Выполнено`, если включена обязательная проверка учителем.
2. Перевод в `На проверке` возможен, если:
   - заполнен хотя бы один ответ: комментарий, файл, ссылка; или
   - включена настройка «разрешить отправку без вложения».
3. При переводе в `Выполнено` система ставит `completed_at`.
4. При переводе из `Выполнено` в другой статус `completed_at` очищается.
5. Статус `Отменено` исключает задачу из прогресса.
6. Все изменения статуса пишутся в историю.

# 10. Подробный функционал сервиса

---

## 10.1. Авторизация и вход

### Требования

- Вход по email и паролю.
- Вход по телефону можно добавить позже.
- Восстановление пароля по email.
- Сессия через JWT или безопасные cookie.
- Пароль хранится только в виде хэша: bcrypt, Argon2 или аналог.
- После 5 неудачных попыток входа — временная блокировка на 10–15 минут.
- Администратор может создать пользователя вручную.
- Для MVP можно не делать самостоятельную регистрацию. Лучше создавать пользователей через администратора или учителя.

### Экраны

- Вход
- Восстановление пароля
- Смена пароля
- Ошибка доступа

### Критерии приёмки

- Ученик видит только свои задачи.
- Учитель видит задачи учеников, к которым имеет доступ.
- Родитель видит только прогресс своего ребёнка.
- Администратор видит административные разделы.

---

## 10.2. Профиль пользователя

### Функции

- Просмотр имени, роли, email.
- Смена пароля.
- Настройка уведомлений.
- Загрузка аватара, опционально.
- Выбор часового пояса.

### Для ученика

- Класс: по умолчанию 8.
- Список активных предметов.
- Краткая статистика: сколько задач в работе, сколько просрочено, сколько выполнено.

### Для родителя

- Привязка к ребёнку.
- Быстрый переход к отчётам.

---

## 10.3. Управление предметами

### Функции для учителя / администратора

- Посмотреть список предметов.
- Включить / отключить предмет.
- Изменить название.
- Задать цвет.
- Задать порядок сортировки.
- Посмотреть количество задач по предмету.
- Посмотреть прогресс по предмету.

### Ограничения

- Нельзя удалить предмет, если по нему есть задачи.
- Вместо удаления — деактивация.
- Деактивированный предмет не отображается у ученика в активных, но история сохраняется.

### Критерии приёмки

- При создании задачи можно выбрать только активный предмет.
- Отключённый предмет не влияет на старые задачи и отчёты.

## 10.4. Создание задачи

### Кто может создавать

- Администратор.
- Учитель.

### Обязательные поля

| Поле | Описание | Валидация |
|---|---|---|
| Название | краткое название задачи | обязательно, 5–200 символов |
| Предмет | выбор из справочника | обязательно |
| Тип задания | урок, ДЗ, тест и т.д. | обязательно |
| Статус | по умолчанию `К выполнению` или `Запланировано` | обязательно |
| Срок выполнения | дата, опционально время | дата в формате `YYYY-MM-DD` |

### Необязательные поля

| Поле | Описание |
|---|---|
| Описание | подробное задание |
| Тема / раздел | группировка внутри предмета |
| Приоритет | низкий, средний, высокий, срочный |
| Плановое время | оценка времени в минутах |
| Максимальный балл | если используется балльная система |
| Формат ответа | файл, текст, ссылка и т.д. |
| Теги | метки |
| Ссылки | внешние материалы |
| Чек-лист | подпункты задачи |
| Вложения | файлы учителя |

### Приоритеты

| Значение | Цвет | Описание |
|---|---|---|
| Низкий | серый | несрочно |
| Средний | синий | обычный приоритет |
| Высокий | оранжевый | важно |
| Срочный | красный | требует внимания |

### Поведение

- После создания задача появляется на доске, в списке и в календаре, если задан срок.
- Ученик получает уведомление, если задача назначена ему.
- Все действия пишутся в историю.

## 10.5. Карточка задачи

Карточка задачи — центральный экран системы.

### Верхняя часть

- Название задачи.
- Предмет с цветом.
- Тип задания.
- Статус.
- Приоритет.
- Срок.
- Оценка / баллы.
- Признак просрочки.

### Вкладки или блоки

1. **Описание**
   - Текст задания.
   - Ссылки.
   - Файлы учителя.
   - Кнопка «Открыть задачу».

2. **Ответ ученика**
   - Поле для текста.
   - Загрузка файлов.
   - Добавление ссылок.
   - Кнопка «Отправить на проверку».

3. **Чек-лист**
   - Список пунктов.
   - Отметка выполнения.
   - Прогресс: например, 3 из 5.

4. **Комментарии**
   - Переписка по задаче.
   - Поле ввода комментария.
   - Отображение автора и времени.

5. **История**
   - Кто и когда изменил задачу.
   - Изменение статусов.
   - Изменение срока.
   - Изменение оценки.

6. **Вложения**
   - Материалы задания.
   - Ответы ученика.

### Действия в карточке

Для учителя:

- редактировать;
- изменить статус;
- поставить оценку;
- добавить комментарий;
- прикрепить файл;
- удалить задачу;
- посмотреть историю.

Для ученика:

- открыть;
- изменить статус в разрешённых пределах;
- добавить ответ;
- добавить комментарий;
- отметить чек-лист;
- указать фактическое время.

Для родителя:

- просмотр;
- при разрешении — комментарий.

Аналог доски в Jira, но упрощённый.

### Колонки по умолчанию

1. Запланировано  
2. К выполнению  
3. В работе  
4. На проверке  
5. Выполнено  
6. Нужно доработать  
7. Отменено  

Для упрощения интерфейса можно отображать 5 основных колонок:

- К выполнению
- В работе
- На проверке
- Выполнено
- Нужно доработать

А статусы «Запланировано» и «Отменено» вынести в фильтр или отдельные секции.

### Карточка задачи на доске

На карточке отображаются:

- название;
- предмет;
- тип задания;
- срок;
- приоритет;
- оценка, если есть;
- индикатор просрочки;
- количество комментариев;
- количество вложений;
- прогресс чек-листа, если есть.

### Функции

- Перетаскивание карточек между колонками.
- Быстрое создание задачи.
- Открытие карточки по клику.
- Фильтры:
  - предмет;
  - статус;
  - приоритет;
  - тип задания;
  - срок;
  - просрочено;
  - сегодня;
  - неделя;
  - поиск по названию.

### Права

- Ученик может перетаскивать только разрешённые статусы.
- Учитель может перетаскивать любые статусы.
- Родитель видит доску в режиме чтения.

### Критерии приёмки

- Изменение статуса через drag-and-drop сохраняется.
- Если у пользователя нет прав на переход, система показывает понятное сообщение.
- Доска быстро загружается при 100–300 задачах.

# 11. Логика прогресса и оценок

---

## 11.1. Прогресс по предмету

Базовая формула:

```text
Прогресс по предмету = количество выполненных задач / количество активных задач × 100%
```

Активные задачи — все задачи, кроме статуса `Отменено`.

Дополнительно можно считать прогресс по баллам:

```text
Прогресс по баллам = сумма полученных баллов / сумма максимальных баллов × 100%
```

Учитываются только задачи, у которых задан максимальный балл.

---

## 11.2. Общий прогресс ученика

Вариант 1, простой:

```text
Общий прогресс = среднее арифметическое прогресса по всем активным предметам
```

Вариант 2, более точный:

```text
Общий прогресс = все выполненные задачи / все активные задачи × 100%
```

Для MVP рекомендуется использовать вариант 2.

---

## 11.3. Оценка

Система поддерживает два варианта:

### 1. Пятибалльная оценка

- 5 — отлично
- 4 — хорошо
- 3 — удовлетворительно
- 2 — неудовлетворительно

Поле `grade`.

### 2. Баллы

- `max_points`
- `earned_points`

Пример:

```text
Максимум: 20 баллов
Получено: 16 баллов
Процент: 80%
```

Для отчётов можно выводить и оценку, и баллы.

---

## 11.4. Правила выставления оценки

- Оценку ставит только учитель или администратор.
- Оценка может быть поставлена в статусе `На проверке` или `Выполнено`.
- Если задача возвращена на доработку, оценка может быть сброшена или сохранена как предварительная — по решению продукта.
- Изменение оценки пишется в историю.

# 12. Комментарии и вложения

---

## 12.1. Комментарии

### Требования

- Текстовый комментарий.
- Длина до 5000 символов.
- Поддержка переносов строк.
- Отображение автора и времени.
- Возможность редактировать свой комментарий.
- Возможность удалять комментарии учителю / администратору.
- История редактирования можно не показывать в MVP, но желательно сохранять.

### Ограничения

- Нельзя оставлять пустой комментарий.
- Нельзя комментировать недоступную задачу.

---

## 12.2. Вложения

### Типы файлов для загрузки

Рекомендуемый список:

- PDF
- DOC / DOCX
- XLS / XLSX
- PPT / PPTX
- JPG / JPEG
- PNG
- GIF
- MP3
- MP4
- ZIP

### Ограничения

- Максимальный размер файла: 20 МБ, настраивается.
- Максимум 10 файлов на одну задачу, настраивается.
- Для больших видео лучше использовать ссылку, а не загрузку файла.
- Имя файла должно сохраняться.
- Система должна проверять тип файла по `mime_type`.
- Желательно хранить файлы в S3-совместимом хранилище или аналоге.

### Категории

- Материалы задания.
- Ответ ученика.

### Критерии приёмки

- Учитель может прикрепить задание.
- Ученик может прикрепить ответ.
- Файлы открываются / скачиваются.
- Чужие пользователи не имеют доступа к файлам без прав на задачу.

# 19. Нефункциональные требования

## 19.1. Производительность

- Загрузка основного списка задач: до 1 секунды при нормальном интернете.
- Загрузка доски: до 2 секунд при 300 задачах.
- Отчёты: до 5 секунд за выбранный период.
- Интерфейс должен работать без полной перезагрузки страницы.

## 19.2. Адаптивность

Обязательная поддержка:

- десктоп: 1280px и выше;
- ноутбук: 1024px;
- планшет: 768px;
- телефон: 375px.

## 19.3. Браузеры

Последние две версии:

- Chrome;
- Firefox;
- Safari;
- Edge;
- Яндекс Браузер.

## 19.4. Безопасность

- HTTPS обязательно.
- Пароли только в виде хэша.
- Защита от перебора пароля.
- Проверка прав доступа на сервере, не только на фронтенде.
- Защита от несанкционированного доступа к чужим задачам.
- Проверка типов и размеров файлов.
- Ограничение доступа к файлам по правам.
- Логирование важных действий.
- Резервное копирование базы данных.

## 19.5. Персональные данные

Так как сервис может использоваться для несовершеннолетних:

- хранить персональные данные минимально необходимо;
- предусмотреть возможность удаления пользователя;
- предусмотреть экспорт данных;
- не передавать данные третьим лицам без необходимости;
- предусмотреть согласие на обработку данных, если это требуется юридически.

## 19.6. Логирование

Сохранять:

- ошибки;
- вход пользователей;
- изменение статусов;
- удаление объектов;
- изменение ролей;
- загрузку файлов.

# 24. Пользовательские сценарии

## 24.1. Учитель создаёт задачу

1. Учитель входит в систему.
2. Нажимает «Создать задачу».
3. Выбирает предмет: например, «Алгебра».
4. Вводит название: «Решить задачи №125–128».
5. Указывает тип: «Домашнее задание».
6. Указывает срок.
7. Добавляет описание и файлы.
8. Сохраняет.
9. Задача появляется у ученика.
10. Ученик получает уведомление.

## 24.2. Ученик выполняет задачу

1. Ученик входит в систему.
2. Видит задачу на дашборде или доске.
3. Открывает карточку.
4. Меняет статус на «В работе».
5. Читает описание.
6. Отмечает пункты чек-листа.
7. Загружает фото решения.
8. Пишет комментарий.
9. Нажимает «Отправить на проверку».
10. Задача переходит в статус «На проверке».

## 24.3. Учитель проверяет работу

1. Учитель получает уведомление.
2. Открывает задачу.
3. Смотрит файлы и комментарий.
4. Если всё верно:
   - ставит оценку;
   - переводит в «Выполнено».
5. Если есть ошибки:
   - пишет комментарий;
   - переводит в «Нужно доработать».

## 24.4. Родитель смотрит прогресс

1. Родитель входит в систему.
2. Видит дашборд.
3. Смотрит прогресс по предметам.
4. Видит просрочки.
5. Видит последние оценки.
6. При необходимости открывает отчёт.

| Риск | Влияние | Как уменьшить |
|---|---|---|
| Перегруженный интерфейс | ученик не поймёт, что делать | делать простой дашборд и доску |
| Слишком много статусов | усложнение процесса | начать с 5–7 статусов |
| Большие файлы | нагрузка на сервер | использовать ссылки для видео |
| Неясные права доступа | утечка данных | проверять права на сервере |
| Изменение требований в процессе | срыв сроков | зафиксировать MVP и отложить второстепенное |
| Родители хотят слишком много функций | усложнение | дать родителю только просмотр и отчёты |
| Плохая работа на телефоне | неудобство | сразу делать адаптивную вёрстку |

9. Нужна ли история редактирования комментариев?

# 28. Итоговое описание продукта для разработчика

Нужно разработать веб-сервис, который представляет собой упрощённый таск-трекер для учебного процесса. Основная сущность — задача, привязанная к предмету. У задачи есть статус, срок, приоритет, тип, описание, вложения, комментарии, чек-лист, оценка и история изменений.

Интерфейс должен включать:

- доску задач;
- список задач;
- календарь;
- карточку задачи;
- дашборд ученика;
- дашборд учителя;
- дашборд родителя;
- отчёты;
- административную панель.

Дмитрий, ниже — дополнение к предыдущему ТЗ. Его можно оформить как отдельный модуль: **«Мотивация, поощрения, рефлексия и аналитика сложности обучения»**.

Этот модуль добавляет:

1. Поощрение ученика за выполнение домашних заданий.
2. Поощрение за прохождение темы / урока.
3. Короткую рефлексию после выполнения задания или темы: где было легко, где сложно.
4. Графики и отчёты для ребёнка и родителя с указанием конкретного урока / темы.
5. Безопасную мотивацию без штрафов, публичного сравнения и давления.

# Дополнение к ТЗ  
## Модуль «Поощрения, рефлексия и аналитика сложности»

---

# 1. Цель модуля

Сделать так, чтобы ученик:

- видел результат своих усилий;
- получал понятное поощрение за выполненные задания и пройденные темы;
- мог коротко отметить, что было легко, а что сложно;
- видел свой прогресс не только в статусах и оценках, но и в визуальной форме;
- не боялся ошибок, а воспринимал рефлексию как способ понять себя.

Для родителя и учителя модуль должен показать:

- по каким темам ребёнку было сложно;
- по каким предметам задания даются легко;
- где систематически возникают трудности;
- как меняется уверенность и сложность со временем;
- за какие уроки ребёнок получил поощрения.

---

# 2. Принципы мотивации

Важно, чтобы система не превратилась в «зарабатывание баллов ради баллов». Поэтому закладываем следующие принципы:

1. **Поощряем усилие, своевременность, завершение и рефлексию, а не только оценку.**
2. **Нет штрафов и отрицательных баллов.**
3. **Нет публичного сравнения с другими учениками.**
4. **Прогресс ребёнка сравнивается только с его собственными прошлыми результатами.**
5. **Рефлексия должна быть короткой и необременительной.**
6. **Баллы и награды не заменяют школьную оценку.**
7. **Учитель и родитель могут вручную поощрять, но не должны использовать баллы как наказание.**
8. **Если задание возвращено на доработку, это не лишает ребёнка возможности получить поощрение после успешного завершения.**

# 3. Новые сущности в системе

Дополнительно к уже описанным сущностям нужно добавить следующие.

## 3.1. Тема / Урок / Topic

Нужна для группировки задач внутри предмета и для отображения графиков по урокам.

Поля:

- `id`
- `subject_id`
- `title`
- `lesson_code`, например: «Урок 12»
- `description`
- `sort_order`
- `planned_date`, опционально
- `is_active`
- `created_at`
- `updated_at`

Пример:

```text
Предмет: Алгебра
Тема: Линейные уравнения
Код урока: Урок 12
```

Задача может быть привязана к теме:

```text
Task.topic_id -> Topic.id
```

Если задача не привязана к теме, в аналитике она может отображаться как «Без темы» или по названию задачи.

---

## 3.2. Прогресс по теме / TopicProgress

Поля:

- `id`
- `student_id`
- `topic_id`
- `status`:
  - `not_started`
  - `in_progress`
  - `review`
  - `completed`
- `progress_percent`
- `total_tasks`
- `done_tasks`
- `started_at`
- `completed_at`
- `updated_at`

Правила определения прохождения темы:

1. Тема считается начатой, если хотя бы одна задача по теме переведена в работу.
2. Тема считается в процессе, если есть задачи в работе или на проверке.
3. Тема считается пройденной, если:
   - все активные задачи темы имеют статус `Выполнено`; или
   - учитель вручную отметил тему как пройденную.
4. Отменённые задачи не учитываются в прогрессе темы.

---

## 3.3. Рефлексия / Reflection

Основная сущность для сбора ощущений ученика.

Поля:

- `id`
- `student_id`
- `task_id`, nullable
- `topic_id`, nullable
- `subject_id`
- `difficulty`: от 1 до 5

- `mood`: emoji или код, опционально

- `what_was_hard`: текст
- `what_helped`: текст, опционально
- `need_help`: true/false
- `actual_minutes`, опционально
- `tags`: массив коротких меток
- `created_at`
- `updated_at`

Рефлексия может быть привязана:

- к конкретной задаче;
- к теме / уроку;
- к предмету в целом, если это итоговая рефлексия.

Для MVP лучше обязательную привязку делать либо к задаче, либо к теме.

# 4. Функционал поощрений

---

## 4.1. За что можно поощрять

Рекомендуемая базовая таблица баллов. Значения должны быть настраиваемыми.

| Событие | Условие | Баллы | Комментарий |
|---|---|---:|---|
| Выполнена задача | статус задачи стал `Выполнено` | 10 | только после принятия учителем |
| Выполнено домашнее задание | задача имеет тип `Домашнее задание` и статус `Выполнено` | 10 | можно суммировать с базовым правилом или использовать отдельное правило |
| Сдано вовремя | `completed_at` не позже `due_date` | 5 | только если задача не отменена |
| Сдано без доработки | задача не переходила в статус `Нужно доработать` | 5 | опционально |
| Заполнена рефлексия | есть рефлексия по задаче или теме | 3 | поощряем самоанализ |
| Пройдена тема | все активные задачи темы выполнены или тема отмечена пройденной | 30 | отдельная награда за завершение темы |
| Серия выполнения | например, 5 дней подряд есть хотя бы одна выполненная задача | 20 | настраивается |
| Прогресс по предмету | 25%, 50%, 75%, 100% | 10–50 | опционально |
| Ручная награда | учитель или родитель отмечает старание | произвольно | с комментарием |

Важно:

- Баллы за оценку не начислять автоматически, чтобы не подменять школьную оценку.
- Можно отдельно вручную поощрить за отличную работу, если учитель считает это уместным.
- Если задача была возвращена на доработку, но потом выполнена, ребёнок всё равно может получить баллы за завершение.
- Баллы за своевременность начисляются, если работа принята вовремя или отправлена на проверку вовремя, в зависимости от настроек.

---

## 4.2. Уровни ученика

Можно добавить уровни на основе накопленных баллов.

Пример:

| Уровень | Название | Минимум баллов |
|---|---|---:|
| 1 | Новичок | 0 |
| 2 | Ученик | 100 |
| 3 | Знаток | 300 |
| 4 | Мастер | 700 |
| 5 | Эксперт | 1500 |
| 6 | Наставник | 3000 |

Формула:

```text
Уровень = определяется по сумме накопленных баллов из RewardTransaction
```

Особенности:

- Уровень не может понижаться.
- Если баллы потрачены на награды, уровень считается по общему количеству заработанных баллов, а не по остатку.
- Ребёнок видит прогресс до следующего уровня: например, «До уровня Знаток осталось 45 баллов».

---

## 4.3. Бейджи и достижения

Бейджи выдаются автоматически или вручную.

Примеры бейджей:

| Код | Название | Условие |
|---|---|---|
| `first_done` | Первая победа | выполнена первая задача |
| `homework_hero` | Герой домашки | выполнено 10 домашних заданий |
| `on_time` | Точно в срок | 5 задач сдано без просрочки |
| `no_rework` | С первого раза | 3 задачи подряд приняты без доработки |
| `reflection_master` | Вдумчивый ученик | заполнено 10 рефлексий |
| `topic_explorer` | Тема закрыта | пройдена первая тема |
| `topic_master` | Мастер тем | пройдено 5 тем |
| `streak_5` | Пять дней подряд | серия из 5 дней с выполненной задачей |
| `comeback` | Не сдаюсь | задача после доработки доведена до выполнения |
| `math_progress` | Прогресс в алгебре | выполнено 10 задач по алгебре |
| `language_progress` | Прогресс в языке | выполнено 10 задач по английскому |
| `creative` | Творческий подход | выполнено 3 творческих задания |
| `speaker` | Оратор | выполнено 3 задания по ораторскому искусству |

Требования:

- Бейдж не может быть выдан повторно за одно и то же событие, если это не многоуровневый бейдж.
- У многоуровневых бейджей должны быть уровни: бронза, серебро, золото.
- Бейджи отображаются в профиле ученика.
- Родитель видит полученные бейджи.
- Бейджи не должны сравнивать ребёнка с другими учениками.

---

## 4.4. Витрина наград

Ученик может видеть:

- текущий баланс баллов;
- общий заработанный балл;
- уровень;
- прогресс до следующего уровня;
- полученные бейджи;
- историю начислений;
- доступные награды, если включено.

Примеры наград:

### Виртуальные награды

- новый стикер;
- рамка аватара;
- тема оформления;
- значок в профиль;
- забавный статус;
- коллекционная карточка.

### Родительские награды

Назначаются родителем вручную.

Примеры:

- прогулка;
- дополнительное время на хобби;
- семейный фильм;
- поход в кафе;
- небольшая покупка;
- освобождение от части домашних обязанностей.

### Учительские награды

Назначаются учителем.

Примеры:

- похвала;
- сертификат;
- выбор роли в групповой работе;
- возможность выбрать тему проекта;
- дополнительный творческий балл.

---

## 4.5. Ограничения и защита от злоупотреблений

Нужно предусмотреть:

1. Одно событие — одно начисление.
2. Нельзя получить баллы за задачу дважды.
3. Нельзя получить награду за тему дважды.
4. Баллы начисляются только после реального завершения события.
5. Баллы за рефлексию начисляются, если рефлексия не пустая.
6. Ручные начисления должны иметь комментарий.
7. Отрицательные баллы запрещены в MVP.
8. Все начисления пишутся в журнал.
9. Администратор может отключить любое правило.
10. Если задание отменено, ранее начисленные баллы можно сохранить или аннулировать только через администратора с комментарием.

# 5. Функционал рефлексии

---

## 5.1. Когда появляется рефлексия

Рефлексия может запрашиваться в трёх случаях:

### 1. После выполнения задачи

Например, ученик завершил домашнее задание.

Система показывает окно:

```text
Как тебе это задание?
Что было легко?
Что было сложно?
Сколько времени ты потратил?
Нужна ли помощь?
```

### 2. После прохождения темы

Например, завершены все задачи по теме «Линейные уравнения».

Система показывает окно:

```text
Тема пройдена!
Оцени, насколько трудной была тема.
Что было самым лёгким?
Что было самым сложным?
Что помогло справиться?
```

### 3. По запросу учителя

Учитель может включить для конкретной задачи флаг:

```text
reflection_required = true
```

Тогда система попросит ученика заполнить рефлексию перед отправкой на проверку или после выполнения.

---

## 5.2. Поля рефлексии

### Обязательные поля для MVP

| Поле | Тип | Описание |
|---|---|---|
| Сложность | шкала 1–5 | 1 — очень легко, 5 — очень сложно |
| Что было легко | текст | короткий ответ |
| Что было сложно | текст | короткий ответ |

### Необязательные поля

| Поле | Тип | Описание |
|---|---|---|
| Уверенность | шкала 1–5 | насколько уверен в материале |
| Настроение | emoji | 😊 😐 😟 |
| Что помогло | текст | учитель, примеры, видео, повторение |
| Нужна помощь | да / нет | сигнал учителю или родителю |
| Фактическое время | минуты | сколько потратил |
| Теги | чипы | быстро выбрать типовые ответы |

---

## 5.3. Шкала сложности

Рекомендуемый формат:

| Значение | Текст | Визуал |
|---|---|---|
| 1 | Очень легко | зелёный смайл |
| 2 | Легко | светло-зелёный |
| 3 | Нормально | жёлтый |
| 4 | Сложно | оранжевый |
| 5 | Очень сложно | красный |

Для ребёнка можно использовать формулировки:

```text
Справился сам без проблем
Было немного трудно
Пришлось подумать
Нужна была помощь
Очень тяжело
```

---

## 5.4. Шкала уверенности

| Значение | Текст |
|---|---|
| 1 | Совсем не уверен |
| 2 | Пока слабо понимаю |
| 3 | В целом понимаю |
| 4 | Почти уверен |
| 5 | Полностью уверен |

---

## 5.5. Быстрые ответы для ребёнка

Чтобы ребёнок не писал много текста, можно предложить чипы.

### Чипы «Было легко»

- Понятное объяснение
- Уже знал эту тему
- Быстро получилось
- Помогли примеры
- Интересное задание
- Справился сам

### Чипы «Было сложно»

- Не понял условие
- Мало времени
- Трудные формулы
- Нужно больше примеров
- Запутался в правилах
- Не хватило объяснения
- Сложно запомнить термины
- Нужно повторить тему

Эти чипы сохраняются как теги и могут использоваться в аналитике.

---

## 5.6. Где видна рефлексия

### Ученик

- видит свои ответы;
- видит историю рефлексий;
- видит графики сложности;
- может вернуться к прошлым ответам.

### Учитель

- видит рефлексию по задачам;
- видит темы, где ученику сложно;
- может ответить поддерживающим комментарием;
- может использовать данные для корректировки плана.

### Родитель

- видит сводные графики;
- видит темы и уроки, где было сложно;
- видит комментарии ребёнка;
- не должен использовать рефлексию для наказания.

# 6. Графики и аналитика сложности

---

## 6.1. Главная идея аналитики

Каждый урок или тема должны быть видимы на графике. Пользователь должен легко понять:

```text
Какой урок?
По какому предмету?
Когда был урок?
Насколько было сложно?
Сколько времени заняло?
Что именно было трудно?
Что было легко?
```

---

## 6.2. Основные графики

---

### График 1. Сложность по урокам

Тип: линейный график.

Ось X:

- уроки / темы по порядку;
- или даты.

Ось Y:

- средняя сложность от 1 до 5.

Каждая точка должна показывать:

- название предмета;
- название урока / темы;
- дату;
- среднюю сложность;
- количество задач;
- статус темы;
- краткие комментарии «что было сложно».

Пример подписи при наведении:

```text
Алгебра — Урок 12. Линейные уравнения
Дата: 12.03.2026
Сложность: 4.2 из 5
Задач: 3
Статус: пройдено
Сложно: перенос слагаемых, знаки
```

---

### График 2. Распределение лёгких, нормальных и сложных заданий

Тип: столбчатая диаграмма или stacked bar.

Категории:

- легко: сложность 1–2;
- нормально: сложность 3;
- сложно: сложность 4–5.

Разрезы:

- по предметам;
- по темам;
- по неделям;
- по месяцам.

---

### График 3. Время на задания

Тип: линейный или столбчатый график.

Показывает:

- плановое время;
- фактическое время.

Разрезы:

- по предмету;
- по уроку;
- по типу задания.

Польза:

- видно, где ребёнок тратит больше времени;
- помогает планировать нагрузку.

---

### График 4. Своевременность выполнения

Тип: столбчатая диаграмма или индикаторы.

Показывает:

- выполнено вовремя;
- выполнено с просрочкой;
- просрочено сейчас.

Можно показывать по:

- предметам;
- неделям;
- типам заданий.

---

### График 5. Прогресс по темам

Тип: прогресс-бары или таблица.

Показывает:

- название темы;
- предмет;
- всего задач;
- выполнено;
- процент прохождения;
- средняя сложность;
- статус.

---

### График 6. Карта сложности по предметам

Тип: тепловая карта или карточки.

Пример:

```text
Алгебра — тема «Линейные уравнения» — сложно
Геометрия — тема «Треугольники» — нормально
Английский — тема «Past Simple» — легко
История — тема «Реформы Петра» — сложно
```

---

## 6.3. Экран «Моя карта обучения» для ученика

Это детский, визуально понятный экран.

На нём можно показать:

- прогресс по предметам;
- пройденные темы;
- текущие темы;
- сложные темы;
- полученные награды;
- серию выполнения;
- уровень.

Визуально можно сделать как «дорожную карту»:

```text
Предмет → темы → уроки → статус → сложность → награда
```

Например:

```text
Алгебра
Урок 10. Формулы — пройдено — легко
Урок 11. Уравнения — пройдено — нормально
Урок 12. Линейные уравнения — сейчас — сложно
Урок 13. Системы уравнений — скоро
```

Для ребёнка важно показывать не только «сложно», но и:

```text
Ты уже справился с похожей темой.
Ты получил награду за настойчивость.
Ты стал быстрее выполнять задания.
```

---

## 6.4. Экран «Рефлексия и сложность» для родителя

Родитель должен видеть более аналитичный экран.

Блоки:

1. Общая сложность за период.
2. Список тем, где было сложно.
3. Список тем, где было легко.
4. Динамика сложности по предметам.
5. Комментарии ребёнка.
6. Запросы о помощи.
7. Время выполнения.
8. Своевременность.

Пример таблицы:

| Предмет | Урок / тема | Дата | Сложность | Комментарий ребёнка | Статус |
|---|---|---|---:|---|---|
| Алгебра | Урок 12. Линейные уравнения | 12.03 | 4.5 | Не понял перенос слагаемых | Пройдено |
| Английский | Unit 5. Past Simple | 14.03 | 2.0 | Было легко, понравилось | Пройдено |
| Физика | Урок 8. Плотность | 15.03 | 4.0 | Трудные формулы | На проверке |

---

## 6.5. Фильтры для графиков

Нужно предусмотреть фильтры:

- предмет;
- период: неделя, месяц, четверть, произвольный диапазон;
- тема;
- тип задания;
- уровень сложности;
- только сложные;
- только лёгкие;
- только с запросом помощи;
- только выполненные вовремя;
- только просроченные.

---

## 6.6. Детализация

Из любого графика должна быть возможность провалиться глубже:

1. Клик по предмету → список тем.
2. Клик по теме → список задач.
3. Клик по задаче → карточка задачи и рефлексия.
4. Клик по точке графика → детали урока.

---

# 7. Как связать поощрения с рефлексией и графиками

---

## 7.1. Сценарий выполнения домашнего задания

1. Ученик выполняет домашнее задание.
2. Прикрепляет ответ.
3. Отправляет на проверку.
4. Заполняет короткую рефлексию.
5. Учитель проверяет работу.
6. Учитель переводит задачу в `Выполнено`.
7. Система начисляет баллы:
   - за выполнение;
   - за домашнее задание;
   - за своевременность, если условие выполнено;
   - за рефлексию, если она заполнена.
8. Ученик получает уведомление:
   ```text
   Отлично! Ты получил 18 баллов за домашнее задание по алгебре.
   ```

---

## 7.2. Сценарий прохождения темы

1. Ученик выполняет задачи по теме.
2. Система считает прогресс темы.
3. Когда все задачи выполнены, тема получает статус `Пройдено`.
4. Ученик заполняет итоговую рефлексию по теме.
5. Система начисляет баллы за тему.
6. При необходимости выдаёт бейдж.
7. Ученик видит:
   ```text
   Тема «Линейные уравнения» пройдена!
   +30 баллов
   Новый бейдж: Тема закрыта
   ```
8. Родитель видит на графике:
   - тема завершена;
   - сложность темы;
   - комментарий ребёнка.

# 14. Требования к отображению графиков

---

## 14.1. Общие требования

- Графики должны быть понятны без технических знаний.
- При наведении должна появляться подсказка.
- Клик по графику должен открывать детали.
- Должны быть фильтры по предмету и периоду.
- Если данных мало, показывать дружелюбное пустое состояние.
- Нельзя показывать сравнение с другими учениками в базовой версии.

---

## 14.2. Подписи сложности

Для детских экранов использовать простые подписи:

```text
Очень легко
Легко
Нормально
Сложно
Очень сложно
```

Для родительских экранов можно использовать цифры:

```text
Средняя сложность: 4.2 из 5
```

---

## 14.3. Цветовая логика

| Уровень сложности | Цвет |
|---|---|
| 1–2 | зелёный |
| 3 | жёлтый |
| 4 | оранжевый |
| 5 | красный |

Цвет должен быть понятен, но не должен выглядеть как тревога или наказание.

# 15. Примеры пользовательских сценариев

---

## 15.1. Ученик выполнил домашнее задание и получил поощрение

1. Ученик открывает задачу по русскому языку.
2. Прикрепляет фото упражнения.
3. Отправляет на проверку.
4. Заполняет рефлексию:
   - сложность: 3;
   - легко: правило;
   - сложно: одно упражнение.
5. Учитель принимает работу.
6. Система начисляет:
   - +10 за выполнение;
   - +10 за домашнее задание;
   - +3 за рефлексию;
   - +5 за сдачу вовремя.
7. Ученик видит уведомление:
   ```text
   Молодец! Ты получил 28 баллов за домашнее задание по русскому языку.
   ```

---

## 15.2. Ученик прошёл тему и получил бейдж

1. По теме «Линейные уравнения» выполнено 3 задачи.
2. Учитель принял все работы.
3. Тема автоматически переходит в статус `Пройдено`.
4. Система предлагает ученику заполнить рефлексию по теме.
5. Ученик отмечает:
   - сложность: 4;
   - сложно: знаки;
   - легко: решение простых уравнений.
6. Система начисляет:
   - +30 за тему;
   - +3 за рефлексию.
7. Ученик получает бейдж:
   ```text
   Тема закрыта
   ```
8. Родитель видит на графике тему с пометкой «сложно, но пройдено».

---

## 15.3. Родитель видит, где ребёнку сложно

1. Родитель открывает раздел «Аналитика».
2. Выбирает период: последние 2 недели.
3. Видит график сложности по предметам.
4. Замечает, что по физике тема «Плотность» имеет сложность 4.5.
5. Открывает детали.
6. Видит комментарий ребёнка:
   ```text
   Трудные формулы, не понимаю, как переводить единицы
   ```
7. Может обсудить это с ребёнком или учителем без давления.

# 16. Этапы разработки модуля

---

## Этап A. Проектирование мотивации и рефлексии

### Работы

- Определить правила начисления баллов.
- Утвердить список бейджей.
- Утвердить шкалы рефлексии.
- Подготовить тексты поддержки.
- Согласовать, можно ли родителю создавать награды.
- Подготовить макеты экранов.

### Форматы результатов

- Список правил поощрения.
- Таблица бейджей.
- Макеты рефлексии.
- Макеты графиков.
- Пользовательские сценарии.

---

## Этап B. Добавление тем / уроков

### Работы

- Создать сущность `Topic`.
- Связать задачи с темами.
- Сделать экран темы.
- Сделать прогресс темы.
- Добавить статусы темы.

### Критерии готовности

- Учитель может создать тему.
- Задачи можно привязать к теме.
- Видно процент прохождения темы.
- Тема может быть отмечена как пройденная.

---

## Этап C. Рефлексия

### Работы

- Создать форму рефлексии.
- Добавить сохранение ответов.
- Показывать рефлексию учителю и родителю.
- Добавить быстрые чипы.
- Добавить уведомления о запросе рефлексии.

### Критерии готовности

- Ученик может заполнить рефлексию после задачи.
- Учитель видит ответы.
- Родитель видит сводку.
- Пустая рефлексия не сохраняется.
- Данные можно использовать в графиках.

---

## Этап D. Баллы, уровни и бейджи

### Работы

- Создать правила поощрения.
- Реализовать транзакции баллов.
- Добавить защиту от повторных начислений.
- Добавить бейджи.
- Добавить уровни.
- Сделать экран наград.

### Критерии готовности

- Баллы начисляются корректно.
- Одно событие не даёт двойного начисления.
- Ученик видит баланс и уровень.
- История баллов доступна.
- Бейджи отображаются после достижения условия.

---

## Этап E. Графики и аналитика

### Работы

- Построить график сложности по урокам.
- Добавить распределение лёгких / сложных заданий.
- Добавить график времени.
- Добавить таблицу сложных тем.
- Добавить фильтры.
- Добавить экспорт.

### Критерии готовности

- Графики отображаются для ученика и родителя.
- В графиках видно название урока / темы.
- Клик по графику открывает детали.
- Данные соответствуют задачам и рефлексии.
- Родитель видит только своего ребёнка.

---

## Этап F. Награды и витрина

### Работы

- Добавить виртуальные награды.
- Добавить родительские награды, опционально.
- Сделать запрос награды.
- Сделать подтверждение родителем.
- Добавить историю наград.

### Критерии готовности

- Ученик видит доступные награды.
- Родитель может подтвердить награду.
- История запросов сохраняется.
- Награды не списываются автоматически без подтверждения, если это настроено.

# 17. Обновлённые критерии приёмки

Модуль считается готовым, если:

1. Учитель может создавать темы / уроки.
2. Задачи можно привязывать к темам.
3. Видно прогресс прохождения темы.
4. Ученик может заполнить рефлексию после задачи или темы.
5. Рефлексия содержит поля «что было легко» и «что было сложно».
6. Ученик получает баллы за выполнение домашнего задания.
7. Ученик получает баллы за прохождение темы.
8. Баллы не начисляются дважды за одно и то же событие.
9. Ученик видит баланс, уровень, бейджи и историю наград.
10. Родитель видит графики сложности по урокам.
11. В графиках отображается название предмета и урока.
12. Можно открыть детали урока и посмотреть комментарии ребёнка.
13. Можно фильтровать аналитику по предмету и периоду.
14. Сложные темы видны отдельно.
15. Лёгкие темы видны отдельно.
16. Нет отрицательных баллов и штрафов.
17. Нет публичного сравнения с другими учениками.
18. Все начисления и награды пишутся в историю.

# 19. Итоговая формулировка для разработчика

Нужно добавить в сервис модуль мотивации и самоанализа.

Он должен:

- начислять ученику баллы за выполненные домашние задания и пройденные темы;
- выдавать бейджи и уровни;
- показывать прогресс до следующего уровня;
- запрашивать у ученика короткую рефлексию после выполнения задания или темы;
- сохранять ответы «что было легко» и «что было сложно»;
- строить графики сложности по урокам и темам;
- давать ребёнку дружелюбную визуальную карту обучения;
- давать родителю понятные графики и таблицы с указанием урока, предмета, даты и комментариев ребёнка;
- не использовать штрафы, отрицательные баллы и публичное сравнение с другими учениками.

Дмитрий, ниже — отдельный блок требований к дизайну. Его можно передать дизайнеру вместе с предыдущим ТЗ. Главный фокус: сделать так, чтобы интерфейс нравился ученику 8 класса и вызывал доверие у родителя, но при этом не выглядел как развлекательная игра или строгий электронный дневник.

# Требования к дизайну сервиса  
## Трекер учебных задач, поощрений и рефлексии для ученика 8 класса

---

# 1. Главная задача дизайна

Дизайн должен решать две параллельные задачи:

## Для ученика

Интерфейс должен восприниматься как:

- понятный помощник;
- личное пространство обучения;
- место, где видно прогресс;
- система, где хвалят, а не наказывают;
- удобный инструмент на телефоне и компьютере;
- не скучный школьный журнал, а современный трекер.

Ученик должен чувствовать:

```text
Я понимаю, что мне делать.
Я вижу, что уже справился.
Меня поддерживают.
Можно ошибиться и продолжить.
Я получаю награды не просто так, а за усилия.
```

## Для родителя

Интерфейс должен восприниматься как:

- спокойный и понятный обзор обучения;
- инструмент поддержки ребёнка;
- источник объективных данных;
- безопасная среда без давления и публичных оценок;
- место, где видно, где ребёнку трудно, а где легко.

Родитель должен чувствовать:

```text
Я понимаю, как идёт обучение.
Я вижу прогресс и проблемные зоны.
Я могу помочь без конфликта.
Сервис не сравнивает моего ребёнка с другими.
Данные представлены бережно и понятно.
```

---

# 2. Возрастная особенность

Ученик 8 класса — это обычно подросток 13–14 лет.

Поэтому дизайн не должен быть:

- слишком детским;
- излишне мультяшным;
- похожим на приложение для младших школьников;
- перегруженным яркими персонажами;
- напоминающим контрольный журнал.

Но он также не должен быть:

- слишком корпоративным;
- сухим;
- тревожным;
- перегруженным таблицами и терминами.

Оптимальный стиль:

```text
Современный, дружелюбный, слегка игровой, но уважающий возраст подростка.
```

Хорошие ассоциации:

- личный прогресс;
- квест;
- прокачка навыков;
- карта обучения;
- достижения;
- спокойная аналитика для взрослых.

---

# 3. Ключевые принципы дизайна

## 3.1. Простота и ясность

Пользователь должен за 3–5 секунд понимать:

- где он находится;
- что происходит;
- какое действие доступно;
- что нужно сделать дальше.

Не должно быть перегруженных экранов, лишних меню и непонятных терминов.

---

## 3.2. Дружелюбие и поддержка

Тон интерфейса должен быть спокойным и поддерживающим.

Плохо:

```text
Задолженность
Ошибка
Не выполнено
Просрочено!
Отстаёт
```

Лучше:

```text
Есть задания, которые ждут
Пока не получилось
Требует внимания
Давай вернёмся к этому
Скоро дедлайн
```

---

## 3.3. Прогресс вместо наказания

Интерфейс должен подчёркивать, что уже сделано, а не только что не сделано.

Например, вместо крупного красного «5 просрочено» лучше показать:

```text
Выполнено: 12 задач
Осталось: 3 задачи
Давай завершим одну из них
```

Просрочки показывать нужно, но без визуального давления.

---

## 3.4. Разные режимы для ученика и родителя

Ученик видит более живой, мотивирующий интерфейс.

Родитель видит более спокойный, аналитический интерфейс.

Нельзя делать один и тот же экран одинаково игровым и для ребёнка, и для родителя.

---

## 3.5. Безопасная мотивация

Не использовать:

- публичные рейтинги;
- сравнение с другими детьми;
- стыдящие формулировки;
- красные тревожные экраны;
- штрафы;
- отрицательные баллы;
- лишение наград за ошибки.

Использовать:

- личный прогресс;
- серии выполнения;
- бейджи;
- уровни;
- похвалу;
- награды за усилия и завершение.

---

## 3.6. Быстрый результат

Ученик должен быстро видеть результат действия:

- изменил статус — карточка визуально обновилась;
- выполнил задачу — появились баллы;
- заполнил рефлексию — получил подтверждение;
- прошёл тему — увидел прогресс и награду.

Важно показывать микроподтверждения:

```text
Готово!
Отлично!
+10 баллов
Тема пройдена
Новый бейдж
```

---

# 4. Визуальный стиль

---

## 4.1. Общее направление

Рекомендуемый стиль:

```text
Современный образовательный SaaS с элементами лёгкой геймификации.
```

Характеристики:

- светлый фон;
- мягкие тени;
- скруглённые карточки;
- аккуратные кнопки;
- понятные иконки;
- умеренные градиенты;
- цветовые метки предметов;
- дружелюбные пустые состояния;
- минимальное количество декоративных деталей.

---

## 4.2. Настроение

Интерфейс должен быть:

- современным;
- спокойным;
- аккуратным;
- живым;
- поддерживающим;
- не детским;
- не агрессивным;
- не бюрократическим.

---

## 4.3. Два визуальных слоя

### Слой ученика

Более эмоциональный:

- яркие акценты;
- бейджи;
- уровни;
- стикеры;
- прогресс-бары;
- лёгкие анимации;
- поддерживающие подписи.

### Слой родителя

Более рациональный:

- спокойные цвета;
- чёткие графики;
- таблицы;
- комментарии ребёнка;
- понятные выводы;
- минимум игровых элементов.

# 5. Цветовая система

---

## 5.1. Базовая палитра

Рекомендуемая основа:

| Назначение | Цвет | Пример |
|---|---|---|
| Основной фон | светло-серый | `#F6F8FB` |
| Поверхность карточек | белый | `#FFFFFF` |
| Основной текст | тёмно-серый | `#111827` |
| Вторичный текст | серый | `#6B7280` |
| Границы, бордюры | светло-серый | `#E5E7EB` |
| Основной акцент | индиго / фиолетовый | `#4F46E5` или `#6366F1` |
| Дополнительный акцент | бирюзовый или голубой | `#06B6D4` |

---

## 5.2. Семантические цвета

| Состояние | Цвет | Использование |
|---|---|---|
| Успех / выполнено | зелёный | `#16A34A` или `#22C55E` |
| В процессе | синий или фиолетовый | `#3B82F6` или `#6366F1` |
| Внимание / скоро срок | янтарный | `#F59E0B` |
| Сложно / требует внимания | оранжевый | `#F97316` |
| Просрочка / критично | красный, но умеренно | `#DC2626` |
| Нейтрально | серый | `#6B7280` |

Важно:

- красный использовать только как сигнал, а не как фон всего экрана;
- не делать просроченные задачи визуально «страшными»;
- для ошибок использовать спокойный красный с понятным пояснением.

---

## 5.3. Цвета сложности

Для рефлексии и графиков:

| Сложность | Цвет | Подпись для ребёнка |
|---|---|---|
| Очень легко | зелёный | Справился сам |
| Легко | светло-зелёный | Было несложно |
| Нормально | жёлтый | Пришлось подумать |
| Сложно | оранжевый | Было трудно |
| Очень сложно | красный | Нужна помощь |

Но цвет не должен быть единственным способом передачи смысла. Нужно добавлять подписи, иконки или форму.

---

## 5.4. Цвета предметов

У каждого предмета должен быть свой цвет или цветной маркер.

Примеры:

| Предмет | Цветовая ассоциация |
|---|---|
| Алгебра | синий |
| Геометрия | фиолетовый |
| Русский язык | красный / коралловый |
| Литература | бордовый / тёплый розовый |
| Английский | бирюзовый |
| География | зелёный |
| История | коричневый / янтарный |
| Биология | салатовый |
| Химия | изумрудный |
| Физика | голубой |
| Информатика | индиго |
| ИЗО | розовый / мультицветный |
| Музыка | пурпурный |
| ОБЖ | тёмно-зелёный |
| Технология | оранжевый |

Цвет предмета должен быть виден:

- на карточке задачи;
- в доске;
- в календаре;
- в списке;
- в графиках;
- в теме / уроке.

- скруглённая форма;
- толщина линии 1.5–2 px;
- размер базовый 24×24;
- понятные без подписи;
- не использовать слишком сложные пиктограммы.

Нужны иконки для:

- задач;
- предметов;
- статусов;
- дедлайнов;
- комментариев;
- файлов;
- наград;
- бейджей;
- рефлексии;
- графиков;
- настроек;
- уведомлений.

---

## 7.2. Иллюстрации

Иллюстрации должны быть:

- современными;
- абстрактными или полуплоскими;
- без чрезмерной детской стилистики;
- поддерживающими, а не развлекающими.

Хорошие сюжеты:

- путь;
- карта;
- рост;
- звёзды;
- книги;
- ноутбук;
- схемы;
- награды;
- планеты;
- маршруты;
- прогресс.

Не использовать:

- infantile персонажей;
- клипарт;
- стоковые фото с неестественными людьми;
- чрезмерно яркие перегруженные сцены.

---

## 7.3. Маскот, опционально

Можно добавить персонажа-помощника, но только если он не выглядит детским.

Лучше:

- минималистичный спутник;
- робот, звезда, книжный дух, маячок;
- появляется редко;
- поддерживает, а не командует.

Пример фразы маскота:

```text
Отличная попытка! Осталось совсем немного.
```

Для 8 класса маскот должен быть скорее стильным, чем милым.

---

# 8. Тон коммуникации

---

## 8.1. Общий тон

Тон должен быть:

- дружелюбным;
- коротким;
- понятным;
- поддерживающим;
- уважительным;
- без канцелярита;
- без иронии и сарказма.

---

## 8.2. Примеры формулировок

| Ситуация | Плохо | Хорошо |
|---|---|---|
| Нет задач | Список пуст | Пока нет задач. Можно начать с новой |
| Просрочка | Просрочено! | Есть задание, которое ждёт. Давай вернёмся к нему |
| Сложная тема | Слабые результаты | Здесь было непросто. Можно попросить помощь |
| Задача выполнена | Выполнено | Отлично! Задача выполнена |
| Нужно доработать | Ошибка | Почти готово. Посмотри комментарий учителя |
| Рефлексия | Отчёт о настроении | Расскажи, как прошло задание |
| Награда | Получены баллы | +10 баллов за выполнение! |

---

## 8.3. Тон для ученика

```text
Ты справишься.
Хороший темп!
Осталось немного.
Отличный прогресс.
Сложно — это нормально.
```

## 8.4. Тон для родителя

```text
Ребёнку может понадобиться поддержка по теме «Линейные уравнения».
За неделю выполнено 12 заданий.
Обратите внимание: по физике было несколько сложных отзывов.
```

---

# 9. Требования к интерфейсу ученика

---

## 9.1. Главная задача ученического интерфейса

Ученик должен быстро видеть:

1. Что нужно сделать сегодня.
2. Что просрочено или скоро.
3. Какой прогресс.
4. Какие есть награды.
5. Где можно получить баллы.
6. Как отметить, что было сложно или легко.

---

## 9.2. Главный экран ученика

Главный экран должен быть персональным.

Пример структуры:

```text
Привет, Маша!
Сегодня у тебя 3 задачи.

[Быстрый список задач на сегодня]

Прогресс недели: 68%
Серия: 4 дня подряд
Баллы: 320
Новая награда: бейдж «Точно в срок»
```

На экране должны быть:

- приветствие по имени;
- задачи на сегодня;
- задачи на этой неделе;
- просроченные, но без давления;
- прогресс-бар;
- небольшой блок наград;
- кнопка «Начать».

---

## 9.3. Карточка задачи для ученика

Карточка должна быть понятной.

На ней нужно показать:

- предмет;
- название;
- срок;
- статус;
- приоритет;
- тип задания;
- сколько баллов можно получить;
- чек-лист, если есть;
- кнопку действия.

Пример кнопок:

```text
Начать
Продолжить
Отправить на проверку
Открыть задание
```

Не нужно показывать ученику служебные технические поля.

---

## 9.4. Доска задач

Для ученика доска должна быть упрощённой.

Рекомендуемые колонки:

```text
Сделать
В работе
На проверке
Готово
Нужно доработать
```

Если колонок слишком много, скрыть служебные статусы в фильтр.

Карточки на доске должны быть:

- крупными;
- цветными по предмету;
- с видимым сроком;
- с понятным статусом;
- с индикатором баллов, если включено.

На мобильном доску можно превратить в свайп-карточки или вертикальный список по колонкам.

---

## 9.5. Рефлексия для ученика

Форма рефлексии должна быть короткой и не выглядеть как тест.

Хороший формат:

```text
Как тебе задание?

😍 Очень легко
🙂 Легко
😐 Нормально
🤔 Сложно
😵 Очень сложно

Что было легко?
[короткое поле]

Что было сложно?
[короткое поле]

Быстрые подсказки:
[Понятно] [Нужно больше примеров] [Запутался] [Не хватило времени]

Нужна помощь?
[Да] [Нет]
```

Требования:

- заполнение не дольше 30–60 секунд;
- крупные элементы;
- эмодзи или простые иконки;
- чипы вместо длинного ввода;
- поле текста необязательное;
- после отправки — поддержка и, если положено, баллы.

---

## 9.6. Награды для ученика

Экран наград должен быть праздничным, но не перегруженным.

Показать:

- баллы;
- уровень;
- прогресс до следующего уровня;
- бейджи;
- последние награды;
- историю начислений.

Визуальные приёмы:

- аккуратная анимация начисления баллов;
- небольшое конфетти при бейдже;
- прогресс-бар уровня;
- карточки бейджей;
- заблокированные бейджи показывать как цели, а не как провал.

Пример:

```text
До уровня «Мастер» осталось 80 баллов
```

---

## 9.7. Карта обучения

Для ученика хорошо подойдёт визуальная карта тем.

Пример:

```text
Алгебра
Урок 10. Формулы — готово
Урок 11. Уравнения — готово
Урок 12. Линейные уравнения — сейчас
Урок 13. Системы — скоро
```

Каждый элемент может показывать:

- статус;
- сложность;
- награду;
- процент выполнения.

Важно: карта должна выглядеть как прогресс, а не как лабиринт ошибок.

---

# 10. Требования к интерфейсу родителя

---

## 10.1. Главная задача родительского интерфейса

Родитель должен быстро понять:

1. Как идёт обучение в целом.
2. Где ребёнок молодец.
3. Где нужна поддержка.
4. Какие темы вызывают трудности.
5. Что ребёнок сам написал в рефлексии.
6. Какие есть награды и достижения.

---

## 10.2. Главный экран родителя

Структура:

```text
Общий прогресс: 74%
На этой неделе: 12 задач выполнено
Просрочено: 2 задачи
Сложные темы: Алгебра — Линейные уравнения
Новая оценка: 5 по английскому
Награда: бейдж «Тема закрыта»
```

Важно показывать сначала хорошее:

```text
Выполнено 12 задач
Ребёнок получил награду за настойчивость
```

Затем зоны внимания:

```text
Можно поддержать в теме «Линейные уравнения»
```

---

## 10.3. Родительские графики

Графики должны быть:

- понятными;
- не перегруженными;
- с подписями;
- с возможностью открыть детали;
- с фильтром по предмету и периоду.

Родитель должен видеть:

- сложность по урокам;
- лёгкие и сложные темы;
- время выполнения;
- своевременность;
- прогресс по предметам;
- награды и достижения;
- комментарии ребёнка.

---

## 10.4. Тон родительских уведомлений

Плохо:

```text
Ваш ребёнок просрочил задание!
У ребёнка проблемы с алгеброй!
```

Хорошо:

```text
По алгебре есть задание, которое требует внимания.
Ребёнок отметил тему «Линейные уравнения» как сложную. Можно мягко поддержать.
```

---

## 10.5. Родитель и награды

Родитель должен понимать:

- за что ребёнок получил баллы;
- что означают бейджи;
- не заменяют ли баллы школьные оценки;
- может ли он сам добавить награду;
- как подтвердить награду, если это предусмотрено.

Нужно предусмотреть объясняющие подсказки:

```text
Баллы — это поддержка за усилия и выполнение заданий. Они не заменяют школьные оценки.
```

---

# 11. Дизайн ключевых экранов

---

## 11.1. Экран входа

Требования:

- минимум полей;
- крупная кнопка входа;
- дружелюбная иллюстрация;
- понятное восстановление пароля;
- отсутствие лишних маркетинговых блоков;
- адаптивность.

Пример:

```text
Вход в учебный трекер
Email
Пароль
[Войти]
Забыли пароль?
```

---

## 11.2. Дашборд ученика

Обязательные блоки:

- приветствие;
- задачи на сегодня;
- быстрый прогресс;
- серия / стрик;
- баллы;
- награда или бейдж;
- задачи, требующие внимания;
- быстрый доступ к предметам.

Визуально:

- крупные карточки;
- один главный акцент;
- кнопки действий заметны;
- нет перегрузки графиками.

---

## 11.3. Дашборд родителя

Обязательные блоки:

- общий прогресс;
- выполнено за период;
- просроченные;
- сложные темы;
- лёгкие темы;
- новые награды;
- комментарии ребёнка;
- графики.

Визуально:

- спокойная палитра;
- чёткая иерархия;
- цифры и графики читаются легко;
- нет игровых элементов на первом плане.

---

## 11.4. Доска задач

Требования:

- колонки должны быть визуально различимы;
- карточки должны быть читаемыми;
- срок должен быть виден;
- просрочка обозначается аккуратно;
- перетаскивание на десктопе;
- на мобильном — удобные действия через меню.

---

## 11.5. Карточка задачи

Структура:

1. Заголовок.
2. Предмет.
3. Статус.
4. Срок.
5. Приоритет.
6. Описание.
7. Чек-лист.
8. Файлы.
9. Комментарий.
10. Кнопка действия.

Для ученика главный акцент:

```text
Что нужно сделать сейчас?
```

Для учителя:

```text
Что проверить?
```

Для родителя:

```text
Что происходит с этой задачей?
```

---

## 11.6. Экран темы / урока

Нужно показать:

- название темы;
- предмет;
- прогресс;
- список задач;
- среднюю сложность;
- награду за прохождение;
- рефлексию ученика.

Пример:

```text
Алгебра
Урок 12. Линейные уравнения

Прогресс: 2 из 3 задач выполнено
Сложность: 4 из 5
Награда за тему: +30 баллов
```

---

## 11.7. Экран рефлексии

Требования:

- крупные элементы;
- выбор сложности в одно касание;
- чипы быстрых ответов;
- текстовые поля необязательны;
- после отправки — поддерживающее сообщение.

Пример после отправки:

```text
Спасибо! Твой ответ поможет лучше понять, что было сложно.
+3 балла за рефлексию
```

---

## 11.8. Экран наград

Структура:

- баланс баллов;
- уровень;
- прогресс до следующего уровня;
- бейджи;
- награды;
- история.

Визуально:

- бейджи как карточки;
- полученные яркие;
- будущие слегка приглушённые;
- без ощущения «ты ещё ничего не получил».

---

## 11.9. Экран графиков

Для родителя:

- графики сложности;
- таблицы сложных тем;
- комментарии ребёнка;
- фильтры;
- экспорт.

Для ученика:

- упрощённая карта;
- эмодзи сложности;
- короткие выводы.

---

# 12. Компоненты дизайн-системы

---

## 12.1. Кнопки

Типы:

- Primary — главное действие.
- Secondary — второстепенное действие.
- Ghost — лёгкая кнопка.
- Danger — destructive action, использовать осторожно.
- Icon button — только иконка, с подсказкой.

Требования:

- высота не меньше 40 px на десктопе;
- touch target не меньше 44×44 px на мобильных;
- явное состояние загрузки;
- понятные состояния:
  - default;
  - hover;
  - focus;
  - active;
  - disabled;
  - loading.

Примеры:

```text
Начать
Сохранить
Отправить на проверку
Готово
Посмотреть награду
```

---

## 12.2. Карточки

Карточка — основной элемент интерфейса.

Требования:

- скругление 12–16 px;
- мягкая тень;
- белый или светлый фон;
- цвет предмета слева или сверху;
- заголовок в 2 строки максимум;
- важные метки видны сразу.

---

## 12.3. Статусы

Статусы должны быть представлены как цветные бейджи.

| Статус | Цвет |
|---|---|
| Запланировано | серый |
| К выполнению | синий |
| В работе | фиолетовый |
| На проверке | янтарный |
| Выполнено | зелёный |
| Нужно доработать | оранжевый |
| Отменено | серый |

Статус не должен передаваться только цветом. Нужен текст или иконка.

---

## 12.4. Приоритеты

| Приоритет | Визуал |
|---|---|
| Низкий | серый |
| Средний | синий |
| Высокий | оранжевый |
| Срочный | красный |

Для ученика можно использовать простые подписи:

```text
Обычное
Важное
Срочное
```

---

## 12.5. Прогресс-бары

Требования:

- скруглённые;
- цвет зависит от контекста;
- показывать процент или долю;
- не делать красный прогресс по умолчанию;
- для незавершённого лучше синий/серый, для завершённого — зелёный.

Пример:

```text
Алгебра: 8 из 10 задач — 80%
```

---

## 12.6. Формы

Требования:

- крупные поля;
- понятные плейсхолдеры;
- подписи над полями;
- ошибки рядом с полем;
- без технических ошибок;
- обязательные поля отмечать аккуратно.

Плохо:

```text
Ошибка 422: field required
```

Хорошо:

```text
Укажите название задачи
```

---

## 12.7. Пустые состояния

Каждый пустой экран должен объяснять:

- что здесь будет;
- почему сейчас пусто;
- что можно сделать.

Пример:

```text
Пока нет задач по этому предмету.
Создайте первую задачу, чтобы начать отслеживать прогресс.
```

Для ученика:

```text
Здесь появятся твои награды. Выполни первую задачу, чтобы начать!
```

---

## 12.8. Загрузчики и ожидания

Использовать:

- скелетоны;
- спиннеры только для коротких действий;
- прогресс загрузки файлов;
- оптимистичные обновления для статусов и чек-листов.

Плохо:

- белый экран;
- долгая загрузка без объяснения;
- техническая ошибка.

---

## 12.9. Ошибки

Требования:

- не пугать;
- объяснять, что делать;
- сохранять введённые данные;
- предлагать повторить.

Пример:

```text
Не получилось сохранить изменения. Проверь интернет и попробуй ещё раз.
```

---

# 13. Дизайн рефлексии

---

## 13.1. Главный принцип

Рефлексия должна ощущаться как короткий личный чек-ин, а не как отчёт или опрос.

---

## 13.2. Элементы

- Эмодзи или иконки для сложности.
- Слайдер или сегментированный выбор.
- Чипы быстрых ответов.
- Короткие текстовые поля.
- Переключатель «Нужна помощь».

---

## 13.3. Визуальный тон

Хорошо:

```text
Расскажи, как прошло задание
```

Плохо:

```text
Оцените уровень сложности выполненной работы
```

---

## 13.4. После отправки

Нужно показать:

```text
Спасибо! Твой ответ сохранён.
+3 балла за рефлексию
```

Если ребёнок отметил «Нужна помощь», показать мягкую подсказку:

```text
Если хочешь, можно написать учителю комментарий или попросить помощи.
```

---

# 14. Дизайн наград и геймификации

---

## 14.1. Принципы геймификации

- Награды должны быть честными.
- Награды должны быть понятными.
- Награды должны отмечать усилия, а не только результат.
- Нельзя лишать наград за ошибки.
- Нельзя сравнивать детей публично.
- Награды не должны становиться самоцелью.

---

## 14.2. Баллы

Визуально:

- значок балла;
- анимация начисления;
- история начислений;
- пояснение, за что начислено.

Пример:

```text
+10 — выполнено домашнее задание
+5 — сдано вовремя
+3 — заполнена рефлексия
```

---

## 14.3. Бейджи

Требования:

- иконка;
- название;
- описание;
- состояние: получен / ещё впереди;
- дата получения;
- контекст, за что получен.

Пример:

```text
Точно в срок
Ты сдал 5 заданий без просрочки
```

---

## 14.4. Уровни

Показать:

- текущий уровень;
- прогресс до следующего;
- короткое поддерживающее сообщение.

Пример:

```text
Уровень: Знаток
До уровня «Мастер» осталось 120 баллов
```

---

## 14.5. Праздничные состояния

Использовать аккуратно:

- лёгкое конфетти при получении бейджа;
- анимация «+ баллов»;
- модальное окно с наградой;
- звук опционально, по умолчанию выключен.

Не использовать постоянные праздничные эффекты, которые мешают.

---

# 15. Дизайн графиков и аналитики

---

## 15.1. Общие требования

Графики должны быть:

- простыми;
- понятными;
- с подписями;
- с подсказками;
- с возможностью детализации;
- адаптированными к мобильному экрану.

---

## 15.2. Для ученика

Использовать:

- упрощённые карточки;
- эмодзи сложности;
- короткие выводы;
- визуальную карту тем.

Пример:

```text
Сложнее всего было на уроке 12. Линейные уравнения
Ты отметил, что трудно с переносом слагаемых
```

---

## 15.3. Для родителя

Использовать:

- линейные графики;
- столбчатые диаграммы;
- таблицы;
- фильтры;
- экспорт.

Пример графика:

```text
Сложность по урокам алгебры за месяц
```

Каждая точка должна показывать:

- урок;
- дату;
- среднюю сложность;
- количество задач;
- комментарий ребёнка.

---

## 15.4. Цвета графиков

- Использовать цветовые метки предметов.
- Для сложности использовать зелёный, жёлтый, оранжевый, красный.
- Не полагаться только на цвет.
- Добавлять подписи, иконки или паттерны.
- Проверять доступность для людей с особенностями цветовосприятия.

---

## 15.5. Пустые графики

Если данных мало:

```text
Пока недостаточно данных. Графики появятся после нескольких выполненных заданий и рефлексий.
```

Не показывать пустые оси и нули без объяснения.

---

# 16. Анимация и микровзаимодействия

---

## 16.1. Где нужна анимация

- Переход статуса задачи.
- Начисление баллов.
- Получение бейджа.
- Заполнение прогресс-бара.
- Открытие карточки.
- Отправка рефлексии.
- Успешное сохранение.

---

## 16.2. Длительность

- Микровзаимодействия: 120–200 мс.
- Переходы экранов: 200–300 мс.
- Праздничные эффекты: не дольше 1–2 секунд.

---

## 16.3. Ограничения

- Не перегружать.
- Не замедлять интерфейс.
- Учитывать настройку `prefers-reduced-motion`.
- Давать возможность отключить праздничные анимации.

---

# 17. Адаптивность

---

## 17.1. Приоритет

Ученики часто будут пользоваться сервисом с телефона, поэтому мобильная версия должна быть полноценной.

Родители чаще смотрят с десктопа, но мобильная версия также должна быть удобной.

---

## 17.2. Основные брейкпоинты

| Устройство | Ширина |
|---|---:|
| Мобильный | 360–480 px |
| Планшет | 768–1024 px |
| Десктоп | 1280 px и выше |

---

## 17.3. Мобильная навигация

Рекомендуется нижняя навигация для ученика:

```text
Главная
Задачи
Календарь
Награды
Профиль
```

Для родителя можно оставить верхнее или боковое меню.

---

## 17.4. Доска на мобильном

Варианты:

- горизонтальный свайп по колонкам;
- список задач с фильтром по статусу;
- карточки задач с быстрым изменением статуса.

Не делать слишком мелкие колонки.

---

## 17.5. Графики на мобильном

- Упрощать.
- Давать переключение периода.
- Показывать детали по тапу.
- Избегать мелких подписей.
- При необходимости поворачивать график в отдельный экран.

---

# 18. Доступность

---

## 18.1. Обязательные требования

- Контраст текста не ниже WCAG AA.
- Все интерактивные элементы доступны с клавиатуры.
- Видимый фокус.
- Альтернативные тексты для иконок и иллюстраций.
- Подписи у полей форм.
- Ошибки формы связаны с полями.
- Цвет не единственный способ передачи смысла.
- Размер тач-элементов не меньше 44×44 px.

---

## 18.2. Читаемость

- Основной текст не меньше 16 px на мобильных.
- Межстрочный интервал 1.4–1.6.
- Достаточные отступы.
- Не использовать слишком узкие контейнеры текста.

---

## 18.3. Эмодзи и иконки

Эмодзи можно использовать, но:

- не как единственный смысловой элемент;
- с текстовой подписью;
- без чрезмерного количества;
- с учётом доступности.

---

# 19. Антипаттерны в дизайне

Необходимо избегать следующих решений.

---

## 19.1. Для ученика

- Слишком детский стиль.
- Перегруженные яркие экраны.
- Много текста без структуры.
- Штрафы и отрицательные баллы.
- Публичные рейтинги.
- Сравнение с другими учениками.
- Красные экраны ошибок.
- Непонятные статусы.
- Сложные термины.
- Долгие формы рефлексии.

---

## 19.2. Для родителя

- Излишняя игровизация.
- Непонятные баллы.
- Графики без подписей.
- Тревожные формулировки.
- Ощущение слежки.
- Много лишних данных на первом экране.
- Отсутствие объяснений, что делать с информацией.

---

## 19.3. Общие

- Медленные экраны.
- Неясные кнопки.
- Отсутствие пустых состояний.
- Технические ошибки в тексте.
- Неудобная мобильная версия.
- Невозможность быстро найти задачу.
- Перегруженные модальные окна.

---

# 21. Сценарии для проверки дизайна

---

## 21.1. Сценарий ученика

Ученик должен быстро:

1. Понять, какие задачи на сегодня.
2. Открыть задачу.
3. Понять, что нужно сделать.
4. Прикрепить ответ.
5. Отправить на проверку.
6. Заполнить рефлексию.
7. Получить баллы или обратную связь.
8. Увидеть свой прогресс.

Желаемое время:

- найти задачу: до 10 секунд;
- понять действие: до 5 секунд;
- заполнить рефлексию: до 60 секунд.

---

## 21.2. Сценарий родителя

Родитель должен быстро:

1. Понять общий прогресс.
2. Увидеть выполненные задачи.
3. Найти сложные темы.
4. Посмотреть комментарии ребёнка.
5. Понять, где нужна поддержка.
6. Увидеть награды и достижения.

Желаемое время:

- найти общий прогресс: до 5 секунд;
- найти сложную тему: до 20 секунд;
- понять причину сложности: до 30 секунд.

---

# 22. Критерии хорошего дизайна

Дизайн можно считать успешным, если:

## Для ученика

- понятно, что делать дальше;
- хочется вернуться;
- виден прогресс;
- награды радуют, но не мешают;
- рефлексия не вызывает раздражения;
- нет ощущения контроля и наказания;
- интерфейс удобно работает на телефоне.

## Для родителя

- быстро понятно, как идёт обучение;
- видно, где ребёнку трудно;
- данные выглядят бережно;
- есть доверие к сервису;
- нет тревожности;
- можно использовать информацию для поддержки ребёнка;
- не приходится разбираться в сложных интерфейсах.

---

# 23. Ключевое дизайн-требование

Итоговое требование можно сформулировать так:

```text
Интерфейс должен быть современным, спокойным и поддерживающим для родителя,
а для ученика — понятным, живым и мотивирующим, без детского стиля,
стыда, давления и перегруженности.
```

Главный баланс:

```text
Для ребёнка — ощущение игры, прогресса и поддержки.
Для родителя — ощущение ясности, пользы и доверия.
```

Главный принцип — простота. Не нужно делать сложную корпоративную Jira. Нужно сделать понятный инструмент, где учитель назначает, ученик выполняет, родитель видит прогресс.
